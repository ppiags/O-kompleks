# Сценарий видео-демонстрации (1–2 минуты)

Динамичный ролик: максимум экрана приложения, минимум кода. Ниже — точный текст, который можно произнести естественно.

## 0:00–0:15 — что это

> Это прототип AI-ассистента для менеджера в CRM. Он анализирует входящее обращение клиента, сверяется с локальной базой знаний и готовит отдельно ответ клиенту и рекомендацию по допродаже.

На экране: общий вид рабочего окна — карточка клиента, история диалога, поле обращения и правая панель AI Assistant.

## 0:15–0:45 — основной сценарий (команда + CRM)

> Возьмём типичный вопрос: клиенту нужен тариф для команды из двенадцати человек и интеграция с CRM. Нажимаю «Проанализировать обращение».

Действия: click по пресету «Команда + CRM», затем по кнопке анализа.

> Ассистент нашёл три релевантные статьи — это видно по бейджам «Найдено в базе знаний». Слева сформирован черновик ответа клиенту: он опирается только на факты из базы, и менеджер проверяет его перед отправкой. Справа — внутренняя подсказка менеджеру: какую допродажу предложить, почему она уместна и какой фразой это сделать. Этот блок клиенту не отправляется.

На экране: блок ответа, блок допродажи, список статей и статус «AI provider: Mock · Knowledge matches: 3».

## 0:45–1:05 — второй сценарий (без допродажи)

> Теперь другое обращение: у клиента не работает вход в личный кабинет. Это вопрос поддержки, а не расширение функциональности.

Действия: click по пресету «Проблема со входом», анализ.

> Ассистент отвечает по существу и честно пишет, что навязывать дополнительный продукт здесь не стоит. Это важнее, чем «продать любой ценой».

## 1:05–1:25 — архитектура и проверки

> Под капотом React и TypeScript на Vite. База знаний локальная, поиск детерминированный и без vector DB. Единый provider adapter: Mock, OpenAI и DeepSeek — провайдер выбирается переменной окружения, интерфейс не меняется. Реальные ключи живут только на сервере, запрос идёт через serverless-функцию api/ai. Есть unit-тесты на retrieval и провайдеры, тесты интерфейса и три Playwright-сценария. Production build и ESLint проходят.

На экране: короткий показ README и структуры проекта.

## 1:25–1:45 — про ИИ-инструменты

> В разработке я использовал DeepSeek Harness как AI coding agent — для ускорения реализации, тестирования и ревью. При этом провайдерная архитектура самого прототипа не привязана к одной модели: Mock, OpenAI и DeepSeek взаимозаменяемы.

## 1:45–2:00 — завершение

> Прототип работает без ключей в demo-режиме и готов к деплою на Vercel. Спасибо за внимание.

## Подсказки для записи

- Пишите экран крупно: зрителю важны ответ клиенту, блок допродажи и бейджи статей.
- Держите под рукой три пресета, чтобы не набирать текст вручную.
- Если нужен live-провайдер, заранее задайте AI_PROVIDER и ключ в .env — статус в шапке покажет OpenAI или DeepSeek вместо Mock.
